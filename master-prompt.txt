## LAYER 9 — DATABASE (sql-database-design standard, Neon Postgres)
**Standards:** 3NF; `uuid` PKs (`gen_random_uuid()`); `timestamptz` everywhere (`created_at`, `updated_at`, soft `deleted_at` where business-relevant); money as **integer KES**; `citext` for emails; enums or lookup tables for statuses; `CHECK` constraints (price ≥ 0, qty ≥ 0, rating 1–5); explicit `ON DELETE` rules on every FK; index every FK and every filter/sort column; partial indexes for hot subsets (`status='published'`); **Drizzle migrations only** (`drizzle-kit`) — no manual schema drift; idempotent seeds.

**Neon specifics:** pooled connection string (`-pooler`) for runtime, **direct** string for migrations; one Neon project, `main` branch = production, **branch per Vercel preview** via the Neon–Vercel integration; extensions `pgcrypto`, `citext`, `pg_trgm`, (`vector` only in P10); search = `tsvector` generated column + GIN, with `pg_trgm` fuzzy fallback for typos ("oxytetracyclin").

**Tables (minimum):**
`users, refresh_tokens, email_verifications, password_resets, addresses, farm_profiles, livestock_groups, reminders, categories, brands, products, product_variants, product_images, inventory_batches, stock_movements, carts, cart_items, bundles, bundle_items, delivery_zones, coupons, coupon_redemptions, orders, order_items, order_events, payments, webhook_events, vet_approvals, prescriptions, reviews, wishlist_items, blog_posts, blog_categories, tags, post_tags, disease_entries, faqs, appointments, questions, bulk_quotes, reseller_applications, contact_messages, newsletter_subscribers, testimonials, staff_profiles, regulators, assets, site_settings, audit_logs.`

**Critical constraints:**
- `product_images`: `UNIQUE(sha256)`, `UNIQUE(url)`, `UNIQUE(product_id) WHERE is_primary` — the database itself enforces "no image used twice".
- `payments`: `UNIQUE(provider, provider_ref)`; `webhook_events`: `UNIQUE(provider, event_id)` — idempotency.
- `inventory_batches`: `qty_on_hand >= 0`, `qty_reserved >= 0`, `qty_reserved <= qty_on_hand`; `expiry_date` required for VET/AGRO classes. Stock decrement inside a transaction with `SELECT … FOR UPDATE`.
- `orders`: `number` human-readable unique (e.g. `SHB-260930-4821`), immutable price snapshot in `order_items`.
- `blog_posts`: cannot be `published` unless `sources` has ≥ 3 entries and `last_verified_at` is set (CHECK/trigger).

**Least privilege:** create `app_rw` role (no DDL, no superuser, no `TRUNCATE`) for runtime; `migrator` role for migrations. Enable **Row Level Security** on user-owned tables (`orders, addresses, farm_profiles, reminders, prescriptions, appointments, wishlist_items, questions`) with policies reading `current_setting('app.user_id', true)`, set per-request via `set_config` inside the transaction. **Deny by default.** App-layer ownership checks are still mandatory (defence in depth).

## LAYER 10 — AUTH & AUTHORIZATION (production-backend-api standard)
- Custom auth (Supabase Auth is gone): email + password, optional phone number captured; **email verification required before checkout of any VET/AGRO item**.
- Passwords: **argon2id** (`@node-rs/argon2`) or bcrypt fallback; min 10 chars; breached-password check via HIBP k-anonymity; never log secrets.
- **Access token** JWT 15 min (`{sub, role}`) in memory; **refresh token** in `httpOnly; Secure; SameSite=Lax` cookie, hashed at rest, **rotated on every use**, reuse of a rotated token revokes the whole family (theft signal).
- Roles: `customer, staff, vet, admin, super_admin`. Two separate middlewares: `authenticate` (identity) then `authorize(...roles)` (permission); services additionally verify **resource ownership** (no IDOR).
- Enumeration-safe errors ("If that email exists, we've sent a link"). Lockout/backoff after repeated failures.
- Optional later: phone-number OTP login via SMS adapter.

## LAYER 11 — COMMERCE, PAYMENTS & SAFETY GATING
- **Payments:** IntaSend — M-Pesa STK Push (primary), card (secondary), pay-on-delivery (only zones flagged `cod_ok`), pay-at-pickup. Build in **sandbox first**.
- Webhook `POST /api/v1/webhooks/intasend`: verify signature/challenge **before** trusting payload → insert `webhook_events` (unique) → if new, hand to `paymentService.settle()` (thin handler, logic in service) → respond 200 fast. Idempotent on transaction reference. Unmatched payments land in an admin reconciliation queue.
- **Order state machine:** `pending_payment → paid → (awaiting_vet_approval) → packed → out_for_delivery/ready_for_pickup → delivered`, plus `cancelled, refunded, payment_failed`. Every transition writes `order_events`.
- **Stock:** reserve for 30 min at checkout start; release on failure/timeout; FEFO (first-expiry-first-out) allocation across batches; block sale of items past minimum shelf-life.
- **Sale classes** (`products.sale_class`):
  - `OTC` — normal flow.
  - `VET_APPROVAL` — account + verified email required; customer uploads a prescription **or** requests vet review; order enters `awaiting_vet_approval`; only role `vet` can approve/reject with reason; customer notified.
  - `AGRO_RESTRICTED` — checkout requires: age ≥ 18 confirmation, PPE + label-reading acknowledgement (checkbox with link to `/safety`), no sale to accounts flagged.
  - `SERVICE_ONLY` — product is bookable, not shippable; "Book vaccination" CTA replaces Add to Cart.
- **Cold chain:** items flagged `cold_chain` only deliverable in zones with `cold_chain_ok` or pickup; checkout blocks otherwise and explains why.
- **Delivery:** zones + fees + ETA in DB; free-delivery threshold from settings; pickup option; fee computed server-side.
- **Coupons:** server-validated; usage limits; no stacking unless flagged.
- **Receipts:** PDF invoice with KRA PIN from config; `EtimsAdapter` interface + stub (real eTIMS integration is a separate, later task — flag it in the report).
- **Reviews:** verified purchasers only, moderated; no incentivised reviews.

## LAYER 12 — ZERO TRUST SECURITY PROTOCOL (mandatory)
1. **Never trust the client.** Prices, totals, stock, discounts, roles, ownership are recomputed/verified server-side on every request.
2. **Deny by default.** Every route requires an explicit policy; unlisted admin routes return 403. RLS deny-by-default in DB.
3. **Validate everything** with Zod at the route boundary (body, query, params, headers, webhook payloads). Client validation is UX only.
4. **Rate limiting** with Upstash (`@upstash/ratelimit`), keyed by **IP + user id** (mobile NAT means IP-only is weak). Limits: login 5/15 min per IP+email · register 5/h · reset 3/h · checkout 10/10 min · search 60/min · contact, quotes, questions 5/h · uploads 10/h. Bot protection: Cloudflare Turnstile (or equivalent) on register, contact, quote, ask-a-vet, checkout.
5. **Headers** via `vercel.json`: strict **CSP** (no inline scripts; nonce/hash), HSTS, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, `frame-ancestors 'none'`.
6. **CSRF:** SameSite cookies + Origin/Referer check + double-submit token on cookie-authenticated mutations.
7. **XSS:** markdown rendered with `rehype-sanitize`; no raw `dangerouslySetInnerHTML` without DOMPurify.
8. **Uploads:** allowlist MIME + **magic-byte** check, ≤ 5 MB, randomised keys, private store, signed URLs with short TTL, strip EXIF.
9. **Secrets:** env only, never in client bundle (grep build output in CI), `gitleaks` in CI, rotate immediately if leaked (and purge history).
10. **Logging:** structured, **no PII, no tokens, no full phone numbers**; audit log for all admin/vet actions (actor, action, entity, before/after, IP).
11. **Dependencies:** Dependabot + `npm audit --omit=dev` gate in CI; lockfile committed.
12. **OWASP Top 10** review in P8 and P9 (injection, broken auth, XSS, IDOR, misconfiguration, SSRF, vulnerable components, logging failures).
13. **Backups & recovery:** rely on Neon point-in-time restore + weekly logical dump (GitHub Action to encrypted artifact/storage); document restore drill in `docs/RUNBOOK.md`.
